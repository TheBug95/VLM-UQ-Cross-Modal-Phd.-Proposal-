**Claim:** MedGemma ships in four public variants, but only two are relevant for our multimodal fundus + VQA experiment. The 4B-IT multimodal model is the correct choice for training-free uncertainty extraction from vision and text hidden states. [^1] [^2]

## 3. Hidden State Extraction: `output_hidden_states=True`

**Claim:** MedGemma (Gemma 3 architecture) supports `output_hidden_states=True` in its `forward()` and `generate()` calls, returning a tuple of hidden states per layer. However, the SigLIP vision sub-model had a known bug in transformers where `output_hidden_states` was not properly cascaded to the vision encoder. [^5] [^6] [^7]

**Source:** Hugging Face transformers GitHub issue #42759, Unsloth GRPO bug report, arXiv paper on Gemma-3 circuit tracing
**URL:** https://github.com/huggingface/transformers/issues/42759, https://github.com/unslothai/unsloth/issues/5121, https://arxiv.org/html/2602.20330v1
**Date:** 2025-12-10 / 2026-04-21 / 2025-11-13
**Excerpt:**
> "Even though I pass the `output_hidden_states=True` to the vision and text model through the config, it seems that the `SiglipModel` class does not successfully cascade this config to the vision and text model."
> "With `UNSLOTH_RETURN_HIDDEN_STATES=1`, I still get vocab-sized logits for both models."
> "The model consists of a SigLIP encoder with patch size 14, applied to 896x896 input images. This produces a grid of 64x64 patches, yielding 4096 initial patch tokens. These tokens are then pooled into 256 soft image tokens before being appended to the text sequence for decoding."

**Context:** For our uncertainty-extraction pipeline, we need hidden states from **both** the vision encoder (MedSigLIP) and the language decoder. The vision encoder bug means we may need to call the vision tower directly (e.g., `model.vision_tower(...)`) rather than relying on the top-level model to return vision hidden states. Alternatively, the `Gemma3ForConditionalGeneration` class returns `hidden_states` for the decoder path, which includes the merged sequence (image tokens + text tokens). The vision-only hidden states can be obtained by extracting the first 256 token positions from the first decoder layer after projection, or by directly invoking `model.vision_tower(pixel_values, output_hidden_states=True)`.
**Confidence:** medium (needs local verification with exact transformers version)

### Code snippet for hidden-state extraction:
```python
# Forward pass with hidden states
outputs = model(
    **inputs,
    output_hidden_states=True,
    return_dict=True,
)

# Decoder hidden states: tuple of (num_layers) tensors
# Each tensor: [batch_size, seq_len, hidden_size=2560]
decoder_hidden_states = outputs.hidden_states  # length = 34+1 (embeddings + 34 layers)

# To get vision-only hidden states, call the vision tower directly:
vision_outputs = model.vision_tower(
    pixel_values=pixel_values,
    output_hidden_states=True,
    return_dict=True,
)
vision_hidden_states = vision_outputs.hidden_states  # tuple of 27+1 tensors
# Final vision features before projection: [batch, 4096, 1152] -> pooled to 256 tokens
```

## 4. MedSigLIP Vision Encoder Architecture

**Claim:** MedGemma's vision encoder is a medically fine-tuned SigLIP-400M (called MedSigLIP). It has 27 transformer layers, hidden size 1152, 16 attention heads, MLP intermediate size 4304, input resolution 896x896, patch size 14, and produces 4096 patches that are pooled to 256 soft tokens before entering the LLM. A 448x448 variant is also released for efficiency. [^1] [^8] [^9] [^10]

**Source:** MedGemma Technical Report (arXiv:2507.05201), Gemma 3 Technical Report, NVIDIA Megatron Bridge docs, Keras Hub docs
**URL:** https://arxiv.org/abs/2507.05201, https://arxiv.org/abs/2503.19786, https://docs.nvidia.com/nemo/megatron-bridge/0.2.0/models/vlm/gemma3-vl.html, https://keras.io/keras_hub/api/models/gemma3/gemma3_backbone/
**Date:** 2025-07-07 / 2025-03-08 / 2025-04-27
**Excerpt:**
> "The vision encoder for Gemma 3 is the 400M variant of the SigLIP encoder and is shared across the different Gemma language model sizes (4B, 27B). The input image resolution is 896x896 with pixel values normalized to [-1, 1]."
> "While the Gemma 3 vision encoder works with 896x896 resolution, we found that many medical vision tasks worked reasonably well at 448x448 resolution. Thus, while the MedGemma 4B image encoder is based on 896x896 resolution for compatibility and consistency with Gemma 3, the released MedSigLIP model is based on 448x448 resolution for more efficient experimentation."
> "Gemma3 uses mm_tokens_per_image=256, with dedicated begin/end/image token indices, and processes images at a fixed 896x896 resolution."
> "Vision encoder: SigLIP with 729M parameters... 27 layers, hidden size 1152, 16 attention heads, intermediate size 4304."

**Context:** The 256 pooled tokens are projected into the LLM embedding space via a single linear projection layer (multi-modal projector). The projection output dimension is 2560 (matching the 4B LLM hidden size). For our KL-divergence uncertainty experiment, we must compare the vision hidden states (shape [batch, 4096 or 256, 1152]) with the text hidden states (shape [batch, seq_len, 2560]). Because the dimensions differ, we either (a) project vision states to 2560, (b) project text states to 1152, or (c) use a shared subspace / alignment layer. The projected vision tokens (after the multi-modal projector) have shape [batch, 256, 2560] and can be directly compared with the first 256 positions of the decoder's merged hidden states.
**Confidence:** high

| MedSigLIP Spec | Value |
|----------------|-------|
| Base architecture | SigLIP-400M (medically fine-tuned) |
| Layers | 27 |
| Hidden size | 1152 |
| Attention heads | 16 |
| MLP intermediate | 4304 |
| Input resolution | 896x896 (MedGemma 4B) / 448x448 (MedSigLIP standalone) |
| Patch size | 14 |
| Initial patches | 64x64 = 4096 |
| Pooled image tokens | 256 |
| Projection output | 2560 (matches LLM hidden dim) |

## 10. Vision-Text Alignment: Cross-Attention or Concatenated Tokens?

**Claim:** MedGemma (Gemma 3 architecture) uses **concatenated tokens with full block attention**, not cross-attention. The 256 vision tokens are projected to the LLM embedding dimension and concatenated with the text token embeddings before being fed into the decoder. The decoder then applies causal (masked) self-attention to the entire sequence. [^22] [^23] [^24] [^25]

**Source:** PaliGemma README (big_vision), GitHub paligemma-from-scratch, arXiv paper on Gemma-3 circuit tracing, arXiv paper on Adapting Lightweight VLMs for RadVQA
**URL:** https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/paligemma/README.md, https://github.com/veronikayurchuk/paligemma-from-scratch, https://arxiv.org/html/2602.20330v1, https://arxiv.org/html/2506.14451v1
**Date:** 2022-04-04 / 2025 / 2025-11-13 / 2025-04-30
**Excerpt:**
> "PaliGemma takes as input one or more images, which are turned into 'soft tokens' by the SigLIP encoder, and input text (codenamed the 'prefix') that is tokenized by Gemma's tokenizer. The image tokens and prefix tokens are concatenated (in this order) and passed to the Gemma decoder with full block-attention, which then generates an output text (the 'suffix') auto-regressively with masked attention."
> "Projection Head: A single linear layer aligns the output dimensionality of the vision tower with the token dimension of the language model's vocabulary, which is required for concatenation."
> "Gemma-3-4B-it processes images using a SigLIP vision encoder, which produces patch tokens that are concatenated with text tokens and fed into a transformer decoder."

**Context:** The absence of cross-attention means that the vision and text representations interact only through the self-attention layers of the decoder. This is crucial for our KL-divergence uncertainty signal: we can extract the projected vision tokens (256 tokens, hidden dim 2560) and the text-prompt hidden states (seq_len tokens, hidden dim 2560) from the same decoder hidden-state tensor. Because they are in the same representation space, we can directly compute divergence metrics (e.g., KL, cosine distance, or MSE between mean-pooled vision and text representations) without needing cross-attention weights. The model applies bidirectional attention over the image tokens (they can attend to each other freely) and causal attention over the generated text tokens. [^22] [^23] [^24]
**Confidence:** high

## 11. Additional Technical Details for the Uncertainty Experiment

### Hidden-State Shapes Summary (for a single image + short prompt)

| Component | Shape | Notes |
|-----------|-------|-------|
| Vision encoder output (before pool) | `[1, 4096, 1152]` | 64×64 patches from 896×896 image |
| Vision encoder output (after pool) | `[1, 256, 1152]` | Pooled via multi-modal projector to 2560 |
| Projected vision tokens (LLM input) | `[1, 256, 2560]` | After `multi_modal_projector` linear layer |
| Text token embeddings | `[1, T, 2560]` | T = number of text tokens in prompt |
| Decoder hidden states (all layers) | `tuple of 35 tensors` | Each: `[1, 256+T, 2560]` (embeddings + 34 layers) |
| Generated token hidden states | `[1, G, 2560]` | G = generated tokens, causal mask applied |

### Key Insight for Uncertainty
Because the image tokens and text tokens are concatenated and processed together in the same self-attention stack, the hidden state at layer `l` for position `i` contains information from both modalities. A simple training-free uncertainty signal can be constructed as:

1. Extract the **mean-pooled vision representation** from the final decoder hidden state: `h_vis = mean(hidden_states[-1][:, :256, :], dim=1)` → `[1, 2560]`.
2. Extract the **mean-pooled text-query representation** from the final decoder hidden state: `h_txt = mean(hidden_states[-1][:, 256:, :], dim=1)` → `[1, 2560]`.
3. Compute **KL divergence** (or a Gaussian approximation) between the distributions implied by `h_vis` and `h_txt`. Alternatively, compute cosine similarity or Euclidean distance.
4. A large divergence indicates modality misalignment → high uncertainty. A small divergence indicates alignment → low uncertainty.

Because the model is not fine-tuned for this task, this is a truly training-free, single-pass approach. The entire extraction happens in one forward pass with `output_hidden_states=True`.

## 12. Risks and Open Questions

1. **Vision hidden-state bug in transformers:** As noted in Hugging Face issue #42759, `SiglipModel` may not properly cascade `output_hidden_states` to sub-components. We should verify locally with `transformers>=4.53.2` and fall back to calling `model.vision_tower(...)` directly if needed. [^5]
2. **Hidden-state dimension mismatch:** Raw vision hidden states are 1152-dim; decoder hidden states are 2560-dim. We must either (a) use the projected vision tokens from the decoder stack, or (b) apply a learned or fixed projection. Using the projected tokens from the decoder is the simplest training-free approach. [^8]
3. **Gated model access:** The checkpoint is gated. We must accept the Health AI Developer Foundations license on Hugging Face before downloading. [^1]
4. **OCT vs. fundus domain shift:** One robustness study noted that "MedGemma has not been specifically fine-tuned for [OCT] modality" and performed poorly on OCT compared to other modalities. Fundus (EyePACS) is in the training mix, so it should be better, but domain shift remains a concern. [^21]
5. **No dedicated medgemma.org API:** All inference must be local. Plan GPU allocation accordingly. [^17]

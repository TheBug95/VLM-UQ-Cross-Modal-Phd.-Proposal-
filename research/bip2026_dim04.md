## 3. Glaucoma Label Distribution & Class Imbalance

```
Claim: Glaucoma (G) is a severe minority class in ODIR-5K. In the original challenge split, glaucoma appears in 207 training cases (out of 3,500 patients), 30 off-site test cases, and 58 on-site test cases, totaling only 307 patients (≈6% of the dataset). Other diseases such as Hypertension (H) are even scarcer (138 total). Because labels are assigned at the patient level, both eyes of a glaucoma-positive patient share the positive label, yielding roughly 614 glaucoma-positive images in training. This extreme imbalance means that AUPRC and per-class F1 are more informative than raw accuracy, and that standard random train/test splits will likely produce unstable glaucoma metrics. [^7][^8][^9]
```

## 4. Patient-Level Labels & Data Leakage Risks

```
Claim: ODIR-5K labels are assigned at the patient level, not independently per eye. Both the left and right fundus images of a given patient receive the same set of multi-label annotations. If a naive split is performed at the image level, eyes from the same patient may end up in both training and test sets, causing data leakage and optimistic performance estimates. The accepted practice is patient-level stratification: all images belonging to a single patient must be placed entirely in one fold (train, validation, or test). Several published implementations explicitly enforce this. [^10][^11][^12]
Source: StackOverflow ODIR discussion / JosueVP17 GitHub / UNSW thesis
URL: https://stackoverflow.com/questions/79885777/odir-5k-should-i-train-a-dual-input-cnn-left-right-or-split-images-for-patien , https://github.com/JosueVP17/transfer-learning-ocular-disease , https://unsworks.unsw.edu.au/bitstreams/6b7e39eb-789c-4a17-8f84-eeb364b6ae4f/download
Date: 2026-03-06 / 2026-03-23 / 2024
Excerpt: "This introduces 'Label Noise.' If a patient has a Cataract only in the Left eye, splitting the data forces the model to treat the healthy Right eye as 'Cataract Positive'... I did train the cnn based on this but it gave horrible results." [^10]; "Patient-level 5-fold split (prevents data leakage)" [^11]; "We adopted patient-level splitting (both eyes of any patient were included either in the training set or in the test set), and five-fold cross-validation was used." [^12]
Context: For a pure inference evaluation on ODIR-5K, we should define a patient-level hold-out test set (e.g., 20% of patients) and perform all inference on both eyes of those patients, aggregating per-patient predictions (e.g., max or average probability) before computing metrics. This mirrors clinical screening where a patient-level decision is desired.
Confidence: high
```

## 5. Preprocessing for MedGemma: Resolution, Color, Normalization

```
Claim: MedGemma-4B (multimodal) uses a SigLIP 400M vision encoder with a fixed input resolution of 896×896 pixels. Pixel values are normalized to the range [-1, 1]. The model expects 3-channel (RGB) inputs. For grayscale modalities (e.g., X-ray), literature recommends channel repetition to create a pseudo-RGB image. For fundus images, which are natively color (RGB), the pipeline should: resize to 896×896 (maintaining aspect ratio via padding if necessary), normalize to [-1, 1], and feed directly. Some implementations also mention CLAHE contrast enhancement as a beneficial preprocessing step for fundus images, but because MedGemma was pretrained on diverse medical images including ophthalmology, heavy hand-crafted enhancement may not be necessary for inference-only setups and could shift the distribution away from pretraining. [^13][^14][^15]
Source: MedGemma Technical Report (arXiv) / MedGemma usage blogs / arXiv preprocessing papers
URL: https://arxiv.org/html/2507.05201v3 , https://blog.csdn.net/weixin_35987118/article/details/158300933 , https://arxiv.org/pdf/2604.23079
Date: 2025-07-12 / 2026-02-23 / 2025
Excerpt: "The input image resolution is 896 × 896 with pixel values normalized to [-1, 1]. MedGemma 4B image encoder is based on 896 × 896..." [^13]; "preprocessed_image = self._normalize_image(image_array); processed_image = self._resize_image(processed_image, (224, 224))" [^14] (note: generic example; MedGemma specifically requires 896×896); "Images were resized to a fixed resolution of 224... CLAHE was applied stochastically during training (p=0.5) and deterministically during validation" [^15]
Context: For the proposed project, a deterministic preprocessing pipeline should be built: (1) Load JPEG, (2) Convert to RGB, (3) Resize to 896×896 using bicubic or Lanczos interpolation, (4) Normalize to [-1, 1] using (pixel / 127.5) - 1.0, (5) Pass to MedGemma tokenizer/processor. Do not apply random augmentation during inference. Optional CLAHE can be evaluated in an ablation but should not be assumed beneficial for a frozen VLM.
Confidence: high
```

**Recommended deterministic preprocessing snippet (PyTorch / Pillow):**

```python
from PIL import Image
import torch
from torchvision import transforms

# MedGemma expects 896x896, [-1, 1] normalized, RGB
medgemma_transform = transforms.Compose([
    transforms.Resize((896, 896), interpolation=transforms.InterpolationMode.BICUBIC),
    transforms.ToTensor(),      # scales to [0, 1]
    transforms.Normalize(
        mean=[0.5, 0.5, 0.5],
        std=[0.5, 0.5, 0.5]    # yields [-1, 1]
    ),
])

def load_fundus(path: str) -> torch.Tensor:
    img = Image.open(path).convert("RGB")
    return medgemma_transform(img)  # shape: [3, 896, 896]
```

```
Claim: For medical VLM yes/no inference, the literature consistently recommends concise, closed-ended prompts with explicit instruction to answer "yes" or "no". ## 7. Evaluation Metrics: What Prior ODIR-5K Papers Report
```

```
Claim: The ODIR-2019 challenge official metrics are per-class AUC, F1-score, and Cohen's Kappa, combined into a "Final score" (arithmetic mean of the three). In glaucoma-specific literature, AUC-ROC, sensitivity, specificity, and F1 are standard. There is an active debate in the ML community about whether AUPRC is universally superior for imbalanced classes. A 2024 NeurIPS paper rigorously argues that AUROC is actually preferable when false negatives are costly (e.g., screening), whereas AUPRC optimizes high-score regions and can introduce subgroup disparities. For glaucoma screening, where missing a positive case is clinically severe, AUROC should be the primary metric, supplemented by AUPRC and per-class F1/sensitivity. [^19][^20][^21]
Source: ODIR challenge derived repos / Nature npj Digital Medicine (GRAPE) / NeurIPS 2024 (A Closer Look at AUROC and AUPRC)
URL: https://github.com/serdna1/ODIR-5K-multi-label-classification/blob/main/README.md , https://www.nature.com/articles/s41746-025-01432-5.pdf , https://arxiv.org/html/2401.06091v4
Date: 2023 / 2025-01 / 2024-01
Excerpt: "Metrics: Kappa score, F1, AUC y score final (este es igual a la media de los tres primeros). Umbral=0.5." [^19]; "The AUC and AUPRC served as our metrics for quantifying both overall glaucoma detection accuracy and group-specific accuracy..." [^20]; "For deployment scenarios with elevated false negative costs, use AUROC... In applications where the consequences of false negatives are especially high, such as in the early screening for critical illnesses like cancer, a primary goal of the model will be to achieve the fewest missed cases; equating to prioritizing model recall." [^21]
Context: The proposed project should report: (1) per-class AUC-ROC for glaucoma, (2) AUPRC for glaucoma as a secondary measure, (3) sensitivity and specificity at the operating point, (4) macro/micro F1 across all 8 labels if multi-label inference is attempted, and (5) Cohen's Kappa if comparing to challenge baselines. Because the setup is inference-only, threshold selection can be done on a small validation patient split or by picking the threshold that maximizes Youden's J on the validation set.
Confidence: high
```

**Consolidated loading and patient-level split snippet:**

```python
import pandas as pd
import numpy as np
from pathlib import Path
from sklearn.model_selection import train_test_split

# ------------------------------------------------------------------
# 1. Load annotations
# ------------------------------------------------------------------
csv_path = "ODIR-5K_Training_Annotations(Updated)_V2.csv"
df = pd.read_csv(csv_path)

# Columns of interest: ID, Patient Age, Patient Sex, Left-Fundus, Right-Fundus,
# Left-Diagnostic-Keywords, Right-Diagnostic-Keywords, N, D, G, C, A, H, M, O

# ------------------------------------------------------------------
# 2. Melt to one-row-per-image while keeping patient-level metadata
# ------------------------------------------------------------------
left = df[["ID", "Patient Age", "Patient Sex", "Left-Fundus",
           "Left-Diagnostic-Keywords", "N", "D", "G", "C", "A", "H", "M", "O"]].copy()
left.rename(columns={"Left-Fundus": "image_path", "Left-Diagnostic-Keywords": "keywords"}, inplace=True)
left["eye"] = "left"

right = df[["ID", "Patient Age", "Patient Sex", "Right-Fundus",
            "Right-Diagnostic-Keywords", "N", "D", "G", "C", "A", "H", "M", "O"]].copy()
right.rename(columns={"Right-Fundus": "image_path", "Right-Diagnostic-Keywords": "keywords"}, inplace=True)
right["eye"] = "right"

images_df = pd.concat([left, right], ignore_index=True)

# ------------------------------------------------------------------
# 3. Patient-level stratified split on glaucoma (G)
# ------------------------------------------------------------------
# One record per patient for stratification
patient_glaucoma = df[["ID", "G"]].drop_duplicates()
train_ids, test_ids = train_test_split(
    patient_glaucoma["ID"],
    test_size=0.20,
    random_state=42,
    stratify=patient_glaucoma["G"]
)

train_df = images_df[images_df["ID"].isin(train_ids)].copy()
test_df  = images_df[images_df["ID"].isin(test_ids)].copy()

# ------------------------------------------------------------------
# 4. Build glaucoma binary target
# ------------------------------------------------------------------
train_df["glaucoma"] = train_df["G"].astype(int)
test_df["glaucoma"]  = test_df["G"].astype(int)

print(f"Train patients: {train_df['ID'].nunique()}, images: {len(train_df)}, glaucoma+ patients: {train_df.loc[train_df['G']==1, 'ID'].nunique()}")
print(f"Test  patients: {test_df['ID'].nunique()},  images: {len(test_df)},  glaucoma+ patients: {test_df.loc[test_df['G']==1, 'ID'].nunique()}")
```

## 10. Cross-Modal KL Divergence for Uncertainty Estimation

```
Claim: The proposed methodology—extracting vision and text features from a frozen VLM and computing cross-modal KL divergence—has direct precedent in the literature. The GroVE paper (2025) introduces probabilistic embeddings for frozen VLMs using Gaussian Process Latent Variable Models and explicitly uses a KL-divergence loss between image and text embedding distributions to enforce alignment. The CRNP paper (ECCV 2022) uses cross-modal random network prediction to estimate uncertainty in medical image segmentation by measuring feature-space divergence. KL divergence between modalities serves as a proxy for epistemic uncertainty: when image and text representations disagree, the model is more uncertain. [^27][^28][^29]
Source: GroVE (arXiv) / CRNP (ECCV) / DUAL uncertainty paper
URL: https://arxiv.org/html/2505.05163v1 , https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136970195.pdf , https://livrepository.liverpool.ac.uk/3195190/1/201395090_April2025.pdf
Date: 2025-05 / 2022 / 2025-04
Excerpt: "We define a KL divergence loss function between the distributions of the image and text embeddings from the GP models... The resulting objective is the mean of the KL divergence in both directions (image-to-text and text-to-image)." [^27]; "CRNP measures the total uncertainty in the feature space for each modality to better guide multi-modal fusion... assigns large weights to the other modality when the current modality is uncertain." [^28]; "UCRL (DUAL-M) ... KL divergence annealing: lambda_KL(t)=lambda_0 * min(1, t/T_warmup) where lambda_0=0.01" [^29]
Context: For MedGemma, one can extract the hidden state of the vision encoder (SigLIP) and the hidden state of the text decoder at the answer token positions, fit Gaussian distributions or deterministic point estimates, and compute KL(image_features || text_features) or a symmetric version. Because MedGemma is generative, an alternative is to compare the likelihood of the "yes" vs "no" answer tokens under the image-conditioned distribution, using the entropy or the probability margin as an uncertainty proxy. The KL approach can be implemented by feeding the image alone through the vision tower to get a distribution, and the text prompt alone through the text tower, then computing KL between the two latent distributions if they are mapped to a common space (e.g., via a small projector trained on in-domain data, or via the pre-aligned Gemma multimodal latent space).
Confidence: high
```

## 12. Practical Recommendations for the BIP 2026 Pipeline

1. **Dataset acquisition:** Download from the official Grand Challenge page or Academic Torrents to avoid Kaggle license ambiguity. Use the `ODIR-5K_Training_Annotations(Updated)_V2.csv` as the ground truth.  
2. **Label extraction:** Create a binary `glaucoma` column from the `G` label. Be aware that glaucoma co-occurs with other diseases (e.g., diabetic retinopathy + glaucoma), so a multi-label evaluation is also valid if the VLM is queried for all 8 categories.  
3. **Splitting:** Always split at the patient level (`ID`). Use stratification on the glaucoma label to ensure the test set contains enough positive cases for stable AUC estimation.  
4. **Preprocessing:** Resize to 896×896, normalize to [-1, 1], RGB. No augmentation at inference. Optional: test CLAHE vs. raw in a small ablation.  
5. **Prompt design:** Use closed-ended yes/no prompts with explicit formatting constraints (e.g., "Final Answer: yes/no"). This simplifies logit extraction and calibration.  
6. **Uncertainty extraction:** Extract vision embeddings from the SigLIP tower and text embeddings from the answer-layer hidden states of the Gemma decoder. Compute a symmetric KL divergence between the two distributions (or use a lightweight projector to align them). High KL = high cross-modal disagreement = high uncertainty.  
7. **Metrics:** Report AUC-ROC (primary), AUPRC (secondary), sensitivity, specificity, F1, and Cohen's Kappa. Use bootstrapping or DeLong's test for confidence intervals given the small glaucoma sample size.  
8. **Reproducibility:** Fix random seeds (42), document the exact MedGemma checkpoint (e.g., `google/medgemma-4b-it`), and publish the patient IDs used in test set to enable external comparison.
